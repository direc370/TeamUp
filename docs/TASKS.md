## 执行顺序

### P0｜竞赛组队对接闭环（当前唯一开发范围）

**目标**：把赛伴做成一个轻量的组队对接平台：队长发布清晰需求，申请人投递一份能被快速判断的加入申请，队长完成审批。

- [ ] 发布组队帖：清晰说明竞赛类型、目标层级、每周投入、缺口技能、项目进展和所需人数。
- [ ] 发现与筛选：按竞赛类型、目标、投入和关键词浏览；移除无证据的匹配百分比、用户数和运营数据。
- [ ] 结构化加入申请：申请人填写角色/贡献方向（最多 3 项）、相关经历（60–200 字）、每周投入档位、适配理由（40–120 字）；作品链接最多 2 条、补充说明选填。
- [ ] 队长申请箱：按“方向、投入、经历、适配理由、链接”查看待处理申请；仅队长可通过或拒绝。
- [ ] 保留安全校验：禁止自己申请、已是成员不可申请、非开放项目不可申请、仅待处理申请可撤回、非队长不可审批。
- [ ] 补齐 DTO/服务/仓储/前端校验和自动化测试；真实数据库迁移不在本轮执行。

**代码完成证据**：前端测试和构建、后端测试和构建均通过；迁移文件已审查但未在真实库执行时必须写“待环境验证”。
