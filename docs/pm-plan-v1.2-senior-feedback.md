# 赛伴计划修订 V1.2（学长访谈后）

日期：2026-09-11  
来源：竞赛学长文字回复（已脱敏，不对外引用姓名）  
性质：对 V1.1「工作台可写」方案的**方向修正**，不是已上线说明。

## 1. 学长原意（压缩成决策）

| 问题 | 学长判断 | 对产品的含义 |
| --- | --- | --- |
| 组队瓶颈 | 主要不是「找不到人」，而是目标、时间和 pal 性对不齐 | 组队页要写成对齐工具，不是招人广场 |
| 招人标准 | 先看每周能否稳定出现，技能其次 | 发布/申请都要有「每周可投入」；技能墙降权 |
| 缺口写清 | 会劝退犹豫的人，这是好事 | 强制写缺口与投入；接受帖子变少、匹配变准 |
| 微信+文档 | 绝大多数队已经够用 | 不要做日常任务管理系统 |
| 接单—验收 | 适合「有一次明确 deadline 的项目」，不适合日常琐事；队长派 + 认领都要有 | 进度只覆盖竞赛里程碑，不做看板全集 |
| 组队+进度同产品 | 会过重；组队像招聘，进度像项目管理，用户不一样 | **先做透组队，进度做成可贴微信的极薄层** |
| 不要做 | 信用分、贡献排名、学院证明 | 维持原「明确不做」；账本本轮继续空着 |
| 会试用的条件 | 真能减少错配；几乎零学习成本；微信能无缝衔接 | 主路径越短越好；输出物优先「复制到微信」 |
| 不会用的条件 | 还要专门打开一个网站管日常进度 | 禁止做重型工作台 |

补充：学长提到大学组队常是熟人/学院内部，平台早期应服务「已有一点关系、但目标没写清」的人，而不是纯陌生人社交。

## 2. 定位改写（替换 V1.1 一句话）

**旧**：入队后 72h 内走完接单→提交→验收。  
**新**：让一帖组队把「缺口、每周时间、目标层级」对齐；进度只保留「本周三件大事」级记录，默认可复制进微信群。

赛伴仍不是法律存证、不是微信替代、不是综测打分器。

## 3. 范围调整

### 本轮只做（P0）

1. **组队对齐（主战场）**
   - 发帖必填：缺口角色（不只技能词）、每周可投入小时、目标层级（探索/省赛/国赛）、周期、线上或线下。
   - 申请必填：动机 ≤80 字、本人每周可投入、可贡献技能。禁止申请自己的帖。
   - 发现页卡片先展示「缺口 + 每周时间 + 目标」，技能标签后置。
   - 去掉或标注未验证的「用户数 / 匹配度百分比」。
2. **入队最小闭环**
   - 队长审批（通过写 Membership，满员关招募）。
   - 「我的队伍」：成员角色只读，不做人脉主页、不做 IM。
3. **进度极薄层（不是工作台产品）**
   - 一队最多展示「当前 1–5 条里程碑」（标题、负责人、截止、状态：未开始/进行中/已完成）。
   - 动作仅：队长创建、指定或认领负责人、标记完成。
   - **不做**：接单时限、阻塞流、待验收驳回循环、分栏看板、贡献账本、信用。
   - 一键「复制本周进度到微信」（完成 / 进行中 / 逾期 三行模板）。

### 从 P0 拿掉（相对 V1.1）

- 完整任务状态机作为用户主路径（待接单→验收闭环不再当北极星）。
- 入队 72h 验收率作为北极星。
- 账本时间线、贡献分展示。
- 「工作台可写四按钮」作为第一 PR 的全部内容。

后端已有的 TaskEvent / 贡献去重**保留代码、产品不暴露**，避免学长说的「多一套没人打开的系统」。

### 仍然明确不做

信用分、排名、学院证明、法律存证、替代微信、陌生人私聊广场、擅自买云。

## 4. 新北极星与护栏

- **北极星**：有效组队帖中，「申请材料含每周投入」且「队长按对齐信息审批」的比例；人工访谈「这人时间目标是否对得上」。
- **次指标**：入队数；「复制到微信」使用次数（有再统计，没有不强行）。
- **护栏**：不把 Mock 人数当运营；文案不写存证；进度页学习成本必须能在 1 分钟内讲完。

## 5. 给下一 Agent 的实现切片

一次 PR 只做组队对齐 + 我的队伍 + 极薄里程碑（可选同一 PR 后半段）。

不要先做重型工作台。

测试：自己申请自己拦截；申请缺每周投入不能提交；满员关入口；B 不能批 A 的队。  
真实 PG / 双账号仍须用户授权后再做，PR 写「未联调」。
